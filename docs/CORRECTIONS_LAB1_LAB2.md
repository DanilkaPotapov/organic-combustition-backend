# Пояснения по исправлениям ЛР1/ЛР2

1. Предметные поля исправлены: вместо `formula` и `molar_mass` используются `carbon_count` и `hydrogen_count`. Фильтр работает по `carbonCount`.
2. Все основные названия домена приведены к `organic_compounds`: таблица, папка backend и API URL.
3. Для ЛР3 добавление принимает настоящие файлы изображения и видео. Имена генерируются на латинице, файлы сохраняются в MinIO, в БД сохраняются имена файлов.
4. В схеме убраны UNIQUE-ограничения. Ограничение «не более одного draft» проверяется бизнес-логикой.
5. В `users` добавлено поле `password_hash` для регистрации и дальнейшей ЛР4.
6. Поля, которые появляются только после публикации, оставлены `NULLABLE`: `short_description`, `carbon_count`, `hydrogen_count`, `formed_at`.
7. JSON услуги формируется одним serializer, поэтому набор полей одинаков для всех ответов; незаполненные поля равны `null`.
8. Успешные ответы не содержат самодельных `statusCode` и `message`.
9. DELETE является soft delete: запись остается в БД со статусом `deleted`, но не передается клиенту.
10. В ЛР3 шаблоны не используются и браузер для показа API не нужен; работа демонстрируется в Postman/Insomnia.
11. Добавлен отдельный документ с порядком скриншотов, чтобы не повторить замечание о пропущенных скриншотах.
12. Диаграмма ЛР3 подготовлена на белом A4 landscape без сетки.

Для файла, который преподаватель требует именно в Word, используй `Исправления_ЛР1_ЛР2.docx` из корня проекта. Перед сдачей вставь в него реальные скриншоты после запуска проекта.
