# ЛР4 — запуск и показ

Потапов Данил, ИУ5-54Б. Открой Docker Desktop, затем в папке проекта выполни `bash scripts/start.sh`. Swagger: http://localhost:3004/api. Вход: potapov@example.local / Potapov123!. Второй пользователь: student2@example.local с тем же паролем. Если .env уже был изменён, используются твои параметры.

## Девять скриншотов по заданию

1. **01_swagger_auth.png.** Открой Swagger в инкогнито. POST /api/users/auth, JSON с email и password, ответ 200. Не публикуй реальные пароли; здесь используются учебные данные.
2. **02_cookie.png.** DevTools → Application → Cookies → localhost. Видны sessionId, HttpOnly, SameSite=Lax. Для личной защиты покажи значение; перед загрузкой скрина в публичный Git скрой значение действующей сессии.
3. **03_swagger_list.png.** В том же Swagger GET /api/organic_compounds?carbonCount=2. Ответ 200, два признака isOwner и isLiked. isOwner меняется для карточек разных авторов.
4. **04_postman_guest_list.png.** Postman GET списка без Cookie и без автоматически сохранённых Cookies; 200, isOwner=0/isLiked=0.
5. **05_postman_user_list.png.** Тот же запрос с Cookie: sessionId=... из браузера; 200, у собственных карточек isOwner=1. Подтверждает, что чтение доступно обоим.
6. **06_postman_guest_publish.png.** Сначала под автором создай черновик POST с ровно name, image, video; сохрани возвращённый id. Теперь выключи Cookie и очисти Cookies. PUT /organic_compounds/{id}/publish с shortDescription, carbonCount, hydrogenCount. Ответ 401, тело пустое.
7. **07_postman_user_publish.png.** Включи Cookie владельца, повтори ровно тот же PUT. Ответ 200; появились значения предметных полей. Если 403 — взят чужой id. Если 409 — карточка уже опубликована, создай новый черновик.
8. **08_redis.png.** В терминале `docker compose exec redis redis-cli --scan --pattern 'session:*'`, затем `docker compose exec redis redis-cli GET 'session:ЗНАЧЕНИЕ'` и `docker compose exec redis redis-cli TTL 'session:ЗНАЧЕНИЕ'`. Видны объект пользователя и оставшийся срок. После logout GET возвращает nil. Значение ключа не помещай в публичный Git до выхода.
9. **09_staruml_signature.png.** Открой uml/Potapov_LR4.mdj в StarUML, диаграмму последовательности, выбери сообщение publish. В Properties поле signature ссылается на операцию publish класса OrganicCompoundsController из той же модели. В файле запрограммировано восемь таких связей. Открытие MDJ в установленном StarUML проверь на Mac; для редактирования картинок есть также Potapov_LR4.drawio.

В каждом Postman-скриншоте оставь видимыми метод, полный URL, параметры/Body, статус и ответ. На Mac: Cmd+Shift+4. PNG сохрани в screenshots/ с именами выше. Скриншоты должны быть получены при твоём запуске.

## Как быстро показать весь бизнес процесс

Auth → список с carbonCount=2 → POST name/image/video → GET draft → PUT publish → GET feed без id → GET feed/{id}?next=true → POST like {"value":1} → POST like {"value":0} → logout. После выхода PUT/POST/DELETE недоступны; GET списка и ленты продолжают работать.

Для переносимых путей перед импортом коллекции в терминале проекта выполни:

```bash
mkdir -p ~/Postman/files
cp postman/files/organic_compound.png postman/files/organic_compound.webm ~/Postman/files/
```

В настройках Postman Working Directory должен указывать на ~/Postman/files. В коллекции сохранены только имена файлов, без повторяющихся папок.

В Postman у файлов image/video заново выбери реальные файлы из postman/files через Select Files. Если жёлтый знак — посмотри подсказку; для рабочего каталога Postman скопируй эти два файла в ~/Postman/files и выбери оттуда. Не пиши заголовок Content-Type вручную для multipart: boundary ставит Postman.

## Что ответить коротко

- Аутентификация проверяет email и пароль; авторизация проверяет права на действие.
- Cookie — данные, которые браузер хранит и автоматически отправляет серверу. У нас там случайный sessionId, HttpOnly закрывает его от JavaScript.
- Сессия — серверная запись о вошедшем пользователе. У нас запись хранится в Redis один час; выход удаляет её.
- Redis — быстрое хранилище ключ–значение. PostgreSQL хранит пользователей и карточки; Redis — временные сессии; MinIO — бинарные файлы.
- JWT — подписанный токен с утверждениями о пользователе. В нашем NestJS используется сессия, JWT нужен для другого варианта курса.
- Swagger описывает API по OpenAPI и позволяет выполнять запросы. Guards проверяют доступ независимо от интерфейса Swagger.
- SSO — единый вход через общий провайдер для нескольких приложений.
- Два фактора — два независимых вида подтверждения личности, например пароль и одноразовый код.
- RSA — асимметричный алгоритм: пара открытого и закрытого ключей; применяется для шифрования и цифровой подписи. Пароли пользователей у нас хешируются bcrypt.
