# Расчёт для 334 пользователей

Проектные допущения: каждый из 334 сотрудников учебной органической лаборатории создаёт 1 карточку органического соединения за рабочий день; 250 дней в году, 8 часов в день. На карточку приходится 8 API запросов по sequence. Пиковая неравномерность 10, запас CPU 1.5. Расчётная производительность 20 RPS на ядро — допущение для планирования, не результат нагрузочного теста.

RPS = 334 × 1 × 8 / (8 × 3600) = 0.0928. Пиковый RPS = 0.928.
CPU = ceil(0.928 × 1.5 / 20) = 1 ядро; выбираем минимум 2 vCPU для приложения и контейнеров. ОП = 2 × 4 = 8 ГиБ.

organic_compounds: id 4; name 480 (120 символов UTF-8 × 4); short_description 960; status 4; image_file_name 255 ASCII; video_file_name 255 ASCII; carbon_count 4; hydrogen_count 4; created_at 8; creator_id 4; formed_at 8. Сумма 1986 байт; с заголовком/выравниванием резерв 2048 байт. Пользователь: 4 + 480 + 640 + 255 + 80 = 1459, резерв 1500 байт. Лайк: три integer по 4 плюс заголовок строки, резерв с индексами 80 байт. На карточку принято 2 лайка.

За 5 лет: 334 × 1 × 250 × 5 = 417500 карточек. БД с резервом индексов 2 × (417500 × (2048 + 2 × 80) + 334 × 1500) = 1844682000 байт = 1.72 ГиБ.
Медиа: 128 КиБ изображение + 512 КиБ видео = 655360 байт на карточку. S3 = 417500 × 655360 = 273612800000 байт = 254.82 ГиБ.
Диск = (1.72 + 254.82) × 1.2 + 20 = 327.85 ГиБ. Выбор: SSD 350 ГиБ для данных, отдельное хранилище резервной копии не менее 350 ГиБ. При более крупных видео объём пересчитать линейно.

Клиент: браузер с HTML5 video, 2 ядра, 4 ГиБ ОП, сетевой доступ. Размеры медиа и активность — заданные проектные оценки.
