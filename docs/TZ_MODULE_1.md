# Техническое задание — модуль 1

## 1. Наименование

Веб-приложение «Organic Analytical» для работы с формулами простых органических соединений и дальнейшего определения неизвестного соединения по продуктам сгорания.

## 2. Основание

Учебный проект по дисциплине «Разработка интернет-приложений», индивидуальная тема №20.

## 3. Назначение

Система предназначена для предоставления справочной информации о простых алканах, алкенах и спиртах. На следующих этапах пользователь сможет формировать заявку с массой образца и объемами CO₂/H₂O и получать рассчитанную формулу и молярную массу.

## 4. Границы ЛР1

В первой лабораторной реализуется только интерфейс услуг: просмотр ленты, отображение единственного черновика и плитка опубликованных карточек с фильтрацией. Изменение серверных данных и расчет заявки не входят в ЛР1.

## 5. Функциональные требования ЛР1

- показать опубликованную карточку по ID в портретной ленте;
- по `next=true` показать следующую опубликованную карточку;
- показать единственный объект в статусе `draft` на странице Добавления;
- позволить визуально менять поля черновика без сохранения;
- вывести опубликованные карточки в плитке из двух столбцов;
- фильтровать плитку на сервере по максимальной молярной массе;
- сохранять введенное значение фильтра после GET-запроса;
- не показывать карточки со статусом `deleted`;
- вычислять количество лайков из массива ID пользователей;
- загружать изображения и видео с MinIO;
- использовать нижнюю навигацию Лента / Добавление / Плитка;
- не использовать клиентский JavaScript и БД.

## 6. Данные услуги

`OrganicCompound` содержит:

- `id` — идентификатор;
- `name` — название;
- `key` — латинский ключ;
- `formula` — химическая формула, поле предметной области №1;
- `molarMass` — молярная масса, поле предметной области №2;
- `description` — текстовое описание;
- `status` — `draft`, `published` или `deleted`;
- `imageUrl` — URL изображения MinIO;
- `videoUrl` — URL видео MinIO;
- `likes` — ID пользователей, поставивших лайк.

В ЛР1 все записи находятся в одной коллекции `ORGANIC_COMPOUNDS`.

## 7. Интерфейс

Интерфейс должен быть портретным. Визуальный прототип — Modern Analytical Sciences. Используется палитра прототипа: `#00B4D8` (cyan), `#0090AE` (dark cyan), `#0F1A24` (основной текст), `#E8F6FA` и `#F0F4F8` (светлые фоны). Все страницы имеют нижнюю панель из трех вкладок. На ленте видео занимает основную часть экрана, а информация и действия размещены поверх него.

## 8. Программная реализация

- TypeScript;
- NestJS;
- Express-платформа NestJS;
- Handlebars;
- отдельный CSS-файл;
- MinIO в Docker Compose;
- Git/GitHub.

## 9. HTTP-интерфейс ЛР1

- `GET /compounds/feed/:id?`;
- `GET /compounds/draft`;
- `GET /compounds/grid?maxMass=...`.

`next=true` является дополнительным query-параметром GET ленты и не создает отдельный обработчик.

## 10. Критерии приемки

Работа считается готовой, если все три страницы открываются, MinIO отдает индивидуальные изображения/видео, плитка фильтруется на сервере, значение фильтра сохраняется, `next=true` работает, удаленный объект скрыт, черновик отображается только на Добавлении, а в исходном коде присутствуют ровно одна коллекция и три GET-обработчика.

## 11. Дальнейшее развитие

В следующих лабораторных предполагается добавить PostgreSQL/ORM, операции изменения данных, бизнес-сущность заявки, вычисление результата по массе образца и продуктам сгорания, REST API, авторизацию и frontend-приложение.
